# Torti — 요구사항 명세 (v0.4 초안)

> 납땜·전자 조립을 비롯한 손작업(3D 프린팅, 목공, 펌웨어 작업 등) 중, 손을 쓰지 않고 **음성으로 질문**하면 **책상 위 캠 화면을 보고** AI가 **음성으로 답해주는** Windows 데스크톱 프로그램.
> 작업(프로젝트)마다 저장소를 분석해 **분야, 역할, 말투, 목소리를 그 작업에 맞춘다.**
>
> 관련 문서: [아이콘 세트 요구사항](ICONS.md)

---

## 1. 배경 및 목표

### 1.1 배경
- 납땜·조립 작업 중에는 양손이 바빠서 검색하거나 키보드를 쓰기 어렵다.
- 책상 위에 웹캠(Elgato)이 있으므로, AI가 작업물을 직접 "보고" 답할 수 있다.

### 1.2 목표
- 페달/단축키 한 번 + 음성 질문 → 수 초 내 음성 답변.
- 질문 시점의 작업물 사진을 AI에게 함께 전달.
- 질문·사진·답변을 자동 기록하여 나중에 복기 가능.

### 1.3 핵심 원칙: Voice-first
**음성 입력 → AI 보조 → 음성 출력**이 메인 플로우다. GUI는 보조 수단(상태 표시, 설정, 기록 열람)이다.

- 작업 중에는 **화면을 보지 않고 키보드를 만지지 않아도** 모든 핵심 동작이 가능해야 한다.
- 상태는 화면이 아니라 **소리(효과음)** 로 알린다.
- 답변은 **귀로 듣기 좋게**: 짧게, 핵심 먼저, 목록·표·기호 없이.
- 제어(다시 듣기, 중단, 새 대화 등)도 **음성 명령**으로 한다.

#### 메인 플로우
```
[트리거: 페달 or 호출어]
   → 🔔 "듣는 중" 효과음
   → 사용자 발화 (발화 끝은 자동 감지, VAD)
   → 🔔 "접수" 효과음 + 캠 캡처
   → STT → (음성 명령이면 즉시 실행 / 질문이면 AI 질의)
   → 답변 음성 재생 (스트리밍, 첫 문장부터)
   → 재생 중 다시 트리거하면 즉시 중단하고 새 질문 듣기
```

### 1.3a 핵심 원칙: 하나의 대화 (유기적 연결)
음성, 텍스트 채팅, 카메라, 자료 이미지, 화면 위치 표시, 작업 저장소, Claude Code 세션이 **하나의 대화와 하나의 작업 맥락을 공유**한다.

- 말로 묻다가 시끄러우면 입력창에 쳐도 같은 대화로 이어진다.
- 카메라로 보던 작업물 대신 회로도를 띄우면, 다음 질문과 위치 표시는 그 회로도 기준이 된다.
- 답은 소리로 하고, 위치는 화면에 강조한다. 화면을 보지 않아도 소리만으로 이해되어야 한다.
- 질문, 답, 메모가 작업 저장소에 쌓이고, 다음에 그 작업을 열면 분석에 반영된다.
- 작업 폴더에서 쓰던 Claude Code 세션도 그대로 불러와 음성이나 채팅으로 이어 간다.

### 1.4 비목표 (Non-goals)
- 실시간 연속 영상 감시 및 자동 경고 (비용·지연 문제로 제외).
- 계측기를 대체하는 정밀 판정 (AI 답변은 **참고용**).
- macOS / Linux 지원 (v1 범위 외).

## 2. 사용 시나리오

| # | 상황 | 사용자 발화 예시 | 기대 동작 |
|---|---|---|---|
| S1 | 부품 식별 | "이 저항 몇 옴이야?" | 캡처 → 색띠 판독 → "4.7kΩ로 보입니다. 멀티미터로 확인하세요." |
| S2 | 납땜 품질 확인 | "방금 납땜한 거 괜찮아?" | 캡처 → 브릿지/냉납 여부 코멘트 |

### 3.6 작업(프로젝트)과 GitHub 연동
실제 제작 작업마다 따로 쓰던 Claude 프로젝트를 Torti에 연결한다. **작업 1개 = GitHub 저장소 1개 = 로컬 폴더 1개**이고, 그 폴더가 Claude CLI의 작업 디렉터리가 된다.

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-50 | **새 작업**: 이름을 받아 템플릿 폴더(`CLAUDE.md`, `NOTES.md`, `datasheets/`, `log/`, `captures/`) 생성 → git 초기화 → GitHub 저장소 연결 후 첫 push. 저장소는 gh CLI로 비공개 자동 생성, 또는 사용자가 만든 빈 저장소 URL 연결 | P0 |
| FR-51 | **이어서 하기**: GitHub 저장소 URL에서 clone, 또는 로컬 작업 선택 후 `git pull`로 최신화하고 시작. 기존 Claude 프로젝트 저장소도 그대로 사용 (기존 `CLAUDE.md` 등은 수정하지 않고 Torti 폴더만 추가) | P0 |
| FR-51a | 작업 폴더의 `CLAUDE.md`를 CLI가 자동으로 읽는다 (`--system-prompt` 사용 시에도 로드됨, M0 확인). 새 작업의 `CLAUDE.md`는 `@NOTES.md`로 메모를 불러온다 | P0 |
| FR-52 | 데이터시트 PDF를 `datasheets/`에 넣으면 CLI가 읽어 참조 (PDF가 있을 때만 Read 도구 허용, 읽기 전용) | P1 |
| FR-53 | 질문·답변을 `log/YYYY-MM-DD.md`에 자동 누적 (시각, 질문, 답변, 사진 파일명) | P0 |
| FR-54 | 음성 메모 "기록해 둬: …" → `NOTES.md`에 시각과 함께 추가 (VC-07을 P0로 상향) | P0 |
| FR-55 | **업데이트(동기화)**: 작업 종료 시 자동 commit + push, 음성 명령 "깃허브에 올려줘/저장해"로 즉시 동기화. 결과는 음성으로 안내 | P0 |
| FR-56 | 사진은 기본적으로 로컬 `captures/`에만 저장하고 저장소에는 올리지 않음 (`.gitignore`). 작업별 옵션으로 켤 수 있음 | P0 |
| FR-57 | push 거부·충돌 시 강제 push나 자동 병합을 하지 않고 음성과 화면으로 알림 | P0 |
| FR-58 | GUI에서 작업 목록, 새 작업, 이어서 하기, 동기화 상태 표시 | P1 |
| FR-59 | **작업 분석 브리핑**: 작업을 열 때 저장소를 읽기 전용(Read/Glob/Grep)으로 분석해 분야, 역할, 요약, 진행 상황, 다음 단계, 핵심 사실, 주의, 용어를 만든다. `.torti/brief.json`에 캐시하고 파일이 바뀌었을 때만 다시 분석. 음성 "작업 다시 살펴봐"로 강제 재분석 | P0 |
| FR-59a | **브리핑 기준 대화**: 일반 상식·배경 설명을 하지 않고 이 작업에 필요한 것만, 기본 한두 문장. 선택지 나열·"필요하면 말씀하세요" 같은 맺음말 금지. "가자/됐다/다음"에는 다음 단계로 받는다 | P0 |
| FR-59b | **분야 적응**: 납땜으로 고정하지 않는다. 작업마다 분야(3D 프린팅, 목공, 펌웨어 등)와 토르티의 역할, STT 용어 힌트를 자동 설정 | P0 |
| FR-59c | **분위기·말투**: 작업 성격(목적, 대상, 위험도)으로 분위기(차분/진지/활기/장난스러움/친근)와 반말/존댓말을 정하고 TTS 속도·음높이에 반영. `NOTES.md`의 "## 말투"가 있으면 우선 | P0 |

## 6. 아키텍처 개요

```
┌──────────────────────── GUI (PySide6) ────────────────────────┐
│  [카메라 미리보기 + ROI]   [대화 로그]   [상태표시: 듣는중/생각중/말하는중] │
└───────────────┬───────────────────────────────────────────────┘
                │ signals/slots
┌───────────────▼───────────── Core Pipeline ───────────────────┐
│ HotkeyListener → AudioRecorder → STT → (CameraCapture + ROI)   │
│        → PromptBuilder(프로젝트 컨텍스트) → ClaudeCliClient(stream) │
│        → TTS(문장 단위) → HistoryStore                          │
└───────────────────────────────────────────────────────────────┘
```

- 각 단계는 인터페이스로 분리하여 엔진 교체 가능 (STT/TTS/LLM).
- 무거운 작업(STT, CLI 호출)은 워커 스레드에서 실행, GUI 블로킹 금지.

### 6.1 Claude CLI 연동 방식
- **호출**: CLI를 headless(비대화형) 모드로 실행하고, 응답을 스트리밍 JSON으로 받아 문장 단위로 TTS에 넘긴다.
- **이미지 전달**: 캡처 이미지를 프로젝트 폴더 내 `captures/`에 저장하고 프롬프트에 파일 경로를 넣어 CLI가 읽게 한다. (스트리밍 JSON 입력으로 이미지 블록을 직접 넣는 방식도 M0에서 비교)
- **작업 폴더**: 작업(GitHub 저장소) 폴더를 CLI 작업 디렉터리로 사용 → `CLAUDE.md`(자동 로드)와 거기서 불러오는 `NOTES.md`, 데이터시트 PDF를 CLI가 참조. 작업이 없으면 `%LOCALAPPDATA%\Torti\workspace` 사용. **Torti 개발 저장소 안의 폴더는 쓰지 않는다** (CLI가 git 루트 기준으로 개발용 메모리 경로를 잡기 때문, M0 확인).
- **이미지 전달 (M0 결정)**: 스트리밍 JSON 입력에 base64 이미지 블록을 직접 넣는다. 파일 경로 + Read 도구 방식은 도구 호출 한 번이 더 들어 첫 토큰이 느리고 토큰도 더 쓴다.
- **세션**: 첫 응답의 세션 ID를 저장해 이후 질문은 같은 세션으로 이어간다. "새 대화" 시 새 세션.
- **시스템 프롬프트**: 음성 친화 답변 규칙(FR-31a)을 CLI의 시스템 프롬프트 추가 옵션으로 주입.
- **권한 제한**: 허용 도구를 파일 읽기 계열로만 제한 (명령 실행·파일 수정 금지). 무인 동작이므로 권한 확인 프롬프트가 뜨지 않도록 설정.
- **상주 프로세스(FR-30b)**: 질문마다 CLI를 새로 띄우면 기동 시간이 추가되므로, 프로세스를 띄워둔 채 스트리밍 입력으로 질문을 이어 보내는 방식을 M1/M2에서 적용.

### 상태 머신
`IDLE → LISTENING → TRANSCRIBING → THINKING → SPEAKING → IDLE`
(어느 상태에서든 취소 단축키 → IDLE)
